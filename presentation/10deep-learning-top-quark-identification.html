At the LHC, a boosted top quark decays into a single collimated spray of particles: a jet. This study asks a simple question. Can machine learning tell that spray apart from an ordinary QCD jet, using nothing but the same dataset, workflow, and evaluation metrics across every architecture we test?

01 · Motivation

Two jets, two histories

A top quark decays through t → Wb, and each W decays further into leptons or quark pairs. When the top is highly boosted, all of these decay products land inside a single narrow cone: a three-pronged internal structure that an ordinary QCD jet never has.

  • Top jets and QCD jets have measurably different internal structure.
  • Machine learning can learn these substructure patterns directly from data.

One config file, one experiment

Configuration covers
  • Input type — high-level / constituent / image / graph
  • Model — architecture class and hyperparameters
  • Optimizer & scheduler — Adam, lr, weight decay, cosine decay
  • Training — epochs, batch size, early stopping patience

Reproducibility: every run is fully determined by its YAML file. Results can be reproduced by re-running train.py --config config.yaml.

04 — Architectures

One loss function for all six

ℒ  =  Σᵢ wᵢ · BCEWithLogits( fθ(xᵢ), yᵢ )  /  Σᵢ wᵢ
fθ: model output (logit)  ·  yᵢ ∈ {0,1}  ·  wᵢ: sample weight from dataset
During training
Output is a raw logit — numerically stable with BCEWithLogitsLoss.
During evaluation
Sigmoid applied to obtain a probability score ∈ [0,1] for ROC / AUC computation.
Early stopping
Stop when validation loss doesn't improve for N epochs. Restore best checkpoint.

Training proceeds in mini-batches. Sample weights, provided by the dataset authors, correct artificial differences in the simulated pT spectra — so the model learns jet substructure, not an artifact of the simulation.

Best epoch, early stopping
Early stopping in action. This is the shape we wanted: training loss falls steadily, while validation loss tracks it, then flattens. Once validation stopped improving, around epoch 60, we let it run a short patience window, roughly eight more epochs, before stopping and restoring that best checkpoint. That checkpoint, not the final epoch, is the one we then evaluated on the held-out test set. It is how model complexity gets chosen without overfitting.

07 — Synthesis

So… which model should we use?

There is no single universal answer. The best model depends on data size · compute budget · representation · hyperparameter tuning.

Best quick baseline

High-level MLP

Strong AUC with minimal data and compute.

Best constituent model (local)

ParticleNet-Lite / GNN

Best at 100k jets — exploits jet topology directly.

Most promising at scale

Graph & symmetry-aware models

Expected gains continue as more training data becomes available.

21
07 — Synthesis

Conclusions

01

We built a modular YAML-based workflow for fair comparison across models.

02

The high-level MLP is a surprisingly strong baseline with little data and low computational cost.

03

Low-level constituent information only helps when the architecture preserves its structure.

04

On the 100k-jet setup, ParticleNet-Lite / GNN is the strongest complex model.

05

Scaling to larger datasets improves performance, especially for higher-capacity models.

06

A final choice needs more data, tuning, and uncertainty studies.

22
08 — Future work

What's next

Scale the remaining models

Constituent MLP, Lorentz-invariant GNN, and Transformer have only been evaluated at 100k jets — the Snellius pipeline is ready to extend that to 1M+.

Hyperparameter tuning

Every architecture used a fixed configuration; a proper sweep — especially for the Transformer — could close much of the observed gap.

Uncertainty quantification

Systematic and statistical uncertainties on AUC and background rejection are needed before any deployment claim.

Symmetry-aware scaling

The Lorentz-invariant GNN is the most promising architecture to test at scale, given its built-in physical constraints.
